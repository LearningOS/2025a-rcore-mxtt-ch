1. 正确进入 U 态后，程序的特征还应有：使用 S 态特权指令，访问 S 态寄存器后会报错。 请同学们可以自行测试这些内容（运行 三个 bad 测例 (ch2b_bad_*.rs) ）， 描述程序出错行为，同时注意注明你使用的 sbi 及其版本。
   
   **程序出错行为**：
   
   1. `ch2b_bad_address.rs`: 非法内存访问

      **错误行为**: 尝试向地址 0x0 写入数据
   
      - **触发异常**: 存储/访问异常 (Store/AMO Access Fault)
      - **原因**: 用户态程序无权访问内核地址空间或未映射的内存区域
      - **表现**: 触发 trap，进入 `__alltraps`，由操作系统处理
   
   2. `ch2b_bad_instructions.rs`: 执行特权指令
   
      **错误行为**: 在用户态执行 `sret` 特权指令
   
      - **触发异常**: 非法指令异常 (Illegal Instruction)
      - **原因**: `sret` 是 S 态特权指令，U 态无权执行
      - **表现**: 执行该指令时立即触发 trap
   
   3. `ch2b_bad_register.rs`: 访问特权寄存器
   
      **错误行为**: 在用户态读取 `sstatus` 特权寄存器
   
      - **触发异常**: 非法指令异常 (Illegal Instruction)
      - **原因**: `sstatus` 是 S 态控制状态寄存器，U 态无权访问
      - **表现**: 执行 `csrr` 指令时立即触发 trap
   
2. 深入理解 trap.S 中两个函数 __alltraps 和 __restore 的作用，并回答如下问题:
   1. L40：刚进入 __restore 时，sp 代表了什么值。请指出 __restore 的两种使用情景。
   
        **sp 代表的值**：刚进入 `__restore` 时，`sp` 指向内核栈上的 `TrapContext` 结构体的起始地址。
   
        **两种使用情景**：
   
        - **中断/异常返回**：处理完中断或异常后，从内核态返回用户态
        - **任务切换恢复**：在任务调度中，当切换到新的用户任务时，恢复该任务的上下文
   
   2. L43-L48：这几行汇编代码特殊处理了哪些寄存器？这些寄存器的的值对于进入用户态有何意义？请分别解释。
   
        ```assembly
            ld t0, 32*8(sp)
            ld t1, 33*8(sp)
            ld t2, 2*8(sp)
            csrw sstatus, t0
            csrw sepc, t1
            csrw sscratch, t2
        ```
   
        **特殊处理的寄存器**：
   
        - **sstatus**：处理器状态寄存器，包含中断使能位、特权级等信息
   
          **意义**：恢复处理器状态，确定返回后的特权级和中断设置
   
        - **sepc**：异常程序计数器，保存发生异常时的指令地址
   
          **意义**：确定返回用户态后继续执行的指令地址
   
        - **sscratch**：临时寄存器，这里用于保存用户栈指针
   
          **意义**：下次陷入内核做准备，保存用户栈指针
   
   3. L50-L56：为何跳过了 `x2` 和 `x4`？
   
        ```assembly
        ld x1, 1*8(sp)
        ld x3, 3*8(sp)
        .set n, 5
        .rept 27
           LOAD_GP %n
           .set n, n+1
        .endr
        ```
   
        **跳过原因**：
   
        - **x2 (sp)**：栈指针将在后面通过 `csrrw sp, sscratch, sp` 指令专门恢复，不能在这里用常规方式加载
        - **x4 (tp)**：线程指针寄存器，应用程序通常不使用，由操作系统管理，所以不需要保存恢复
   
   4. L60：该指令之后，`sp` 和 `sscratch` 中的值分别有什么意义？
   
        ```assembly
        csrrw sp, sscratch, sp
        ```
   
        **执行后**：
   
        - **sp**：从 `sscratch` 加载，现在指向用户栈指针
        - **sscratch**：从原来的 `sp` 加载，现在指向内核栈指针（为下次陷入做准备）
   
   5. `__restore`：中发生状态切换在哪一条指令？为何该指令执行之后会进入用户态？
   
        **状态切换指令**：`sret`
   
        **为何会进入用户态**：
   
        - `sret` 指令从 `sepc` 寄存器读取返回地址
        - 根据 `sstatus` 寄存器中的 `SPP` 字段确定目标特权级
        - 将程序计数器设置为 `sepc` 的值，并切换到用户模式
   
   6. L13：该指令之后，`sp` 和 `sscratch` 中的值分别有什么意义？
   
        ```assembly
        csrrw sp, sscratch, sp
        ```
   
        **执行后**：
   
        - **sp**：从 `sscratch` 加载，现在指向内核栈指针
        - **sscratch**：从原来的 `sp` 加载，现在指向用户栈指针
   
   7. 从 U 态进入 S 态是哪一条指令发生的？
   
        **从用户态进入内核态的指令**：`ecall`
   
        当用户程序执行 `ecall` 指令时，会触发环境调用异常，处理器从用户态(U)切换到监管态(S)，跳转到 `stvec` 寄存器指定的异常处理入口（即 `__alltraps`）。
