1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

   ```
   [63:54] - 保留位
   [53:10] - PPN（物理页号），44位
   [9:8]   - RSW（保留给软件使用）
   [7]     - D（Dirty） - 脏位，页面被写入时硬件自动设置
   [6]     - A（Accessed） - 访问位，页面被访问时硬件自动设置
   [5]     - G（Global） - 全局位，TLB全局映射，在ASID切换时不被刷新
   [4]     - U（User） - 用户位，为1时用户模式可访问，为0时只能在监督者模式访问
   [3]     - X（Execute） - 可执行，控制页面的执行权限
   [2]     - W（Write） - 可写，控制页面的写权限
   [1]     - R（Read） - 可读，控制页面的读权限
   [0]     - V（Valid） - 有效位，表示该页表项是否有效
   ```

   

2. 缺页

   缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

   - 请问哪些异常可能是缺页导致的？
     - **指令页错误**（Instruction Page Fault）
     - **加载页错误**（Load Page Fault）
     - **存储页错误**（Store Page Fault）
   - 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
     - **scause**：异常原因（12=指令页错误，13=加载页错误，15=存储页错误）
     - **stval**：出错的虚拟地址
     - **sepc**：发生异常的指令地址
     - **sstatus**：处理器状态信息

   缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

   - 这样做有哪些好处？
     1. **减少启动延迟**：程序启动时无需立即加载所有代码段
     2. **节省内存**：只加载实际被执行的代码页面
     3. **提高效率**：避免加载可能永远不会执行的代码（如错误处理分支）

   其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

   - 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

     每个页表项 8 字节，10G 内存需要 10G/4K = 2.5M 个页面，直接映射需要 2.5M × 8B = 20MB，考虑多级页表结构，实际占用约 20-40MB 数量级

   - 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

     1. **初始分配**：建立页表映射时设置 PTE 的 V=0，但记录后备存储信息
     2. **缺页处理**：当访问 V=0 的页面时触发缺页，在异常处理中：
        - 分配物理页帧
        - 从磁盘加载数据到内存
        - 设置 PTE 的 V=1 和相应权限位
        - 重新执行触发缺页的指令

   - 缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。此时页面失效如何表现在页表项(PTE)上？

     当页面被换出到磁盘时，PTE 的 **V=0**，但其他位可能用于存储：

     - 磁盘位置信息（在交换分区中的位置）
     - 页面状态标志
     - 当访问时，通过 V=0 触发缺页，然后从磁盘换入

3. 双页表与单页表

   为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 [KPTI](https://en.wikipedia.org/wiki/Kernel_page-table_isolation) )

   - 在单页表情况下，如何更换页表？

     通过修改 **satp** 寄存器：

     ```assembly
     csrw satp, new_page_table_root
     sfence.vma  // 刷新 TLB
     ```

     

   - 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

     通过 PTE 的 **U 位**控制：

     - 内核页面：U=0，用户态访问会触发页错误
     - 用户页面：U=1，用户态可正常访问

   - 单页表有何优势？（回答合理即可）

     1. **性能更好**：用户态-内核态切换时无需切换页表，减少 TLB 刷新
     2. **实现简单**：只需维护一套页表
     3. **内存节省**：减少页表内存占用

   - 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？

     1. **双页表更换页表时机：**
        - **进程切换时**：切换到新进程的用户页表
        - **进入内核时**：切换到内核页表
        - **返回用户时**：切换回用户页表

     2. **单页表更换页表时机：**

        我会选择在**进程切换时**更换页表：

        - 每个进程有独立的地址空间映射
        - 内核空间在所有进程页表中保持相同映射
        - 切换代价较小，只需修改 satp 寄存器
